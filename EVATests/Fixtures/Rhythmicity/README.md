# Rhythmicity milestone 0 reference lock

This directory pins the external numerical behavior EVA needs for LAVI and
ABBA milestones 1–5 and the independent paper-equation WTPL oracle added for
milestone 6. The executable upstream LAVI oracle is the **Python implementation
only**, at the exact commit recorded in `upstream-manifest.json`; the WTPL
fixture is generated by EVA's intentionally independent, standard-library-only
Python oracle. MATLAB is not required to regenerate or test these fixtures.

Scientific method: Karvat et al., “Local auto-correlated vector index for
frequency-specific rhythmicity detection,” *Nature Communications* 17, 7024
(2026), https://doi.org/10.1038/s41467-026-73553-8.

The committed inputs are synthetic and EVA-owned. No participant EEG samples
are stored here. The two supplied MFF recordings remain external integration
inputs; only deidentified structural metadata and cryptographic hashes appear
in `mff-integration-manifest.json`.

## Numerical decisions

### LAVI definition

For each frequency, the maintained Python implementation uses the normalized
complex inner product from Equation 2 of the paper. If `z[t]` is the complex
wavelet coefficient and the exact lag in samples is `w = lagCycles / f * fs`,
then:

1. `wi = floor(w)` and `r = w - wi`;
2. the future coefficient is linearly interpolated in the complex plane as
   `(1-r) z[t+wi] + r z[t+wi+1]`;
3. the final sample is excluded even when `r == 0`, matching the maintained
   array slices;
4. invalid edge pairs are removed; and
5. LAVI is the magnitude of the normalized complex inner product.

EVA will implement this fractional-complex rule. It will not use the commented
legacy integer rule or interpolate wrapped angles.

The maintained code drops pair positions based on NaNs in its first channel
when `compute_lavi` receives multiple channels. EVA will instead process each
channel and valid segment independently, which matches the authors'
`Prepare_LAVI` channel loop and prevents one channel's mask from contaminating
another.

### Morlet convention

The Python oracle translates the FieldTrip-style LAVI wavelet: five cycles,
Gaussian support of ±3 standard deviations, no zero-mean correction, and
invalid output where the complete wavelet is not immersed in the signal. Its
sample-count construction can produce an even kernel and therefore a
half-sample center phase.

EVA's existing `ComplexMorlet` is intentionally MNE-compatible: odd support
with a sample exactly at zero, ±5 standard deviations, and a zero-mean default.
The spike test found the expected unit-complex center offset, but more
importantly found a maximum LAVI difference of approximately `0.54524` on the
deterministic fixture (at the lowest default frequency). That is too large for
paper parity.

**Decision:** milestone 1 must add a distinct FieldTrip/LAVI-2026 convention.
Do not modify the MNE-compatible kernel used by ERSP and ITPC. Constant
normalization may be optimized because it cancels from LAVI, but sampled
support, centering, phase orientation, FFT/cropping behavior, and valid-edge
mask must match `python-reference.json`.

### ABBA

The fixture pins both Python outputs and MATLAB-compatible 1-based indices.
The required behavior is:

- finite-value median across frequencies;
- exact-median values inherit one tenth of the preceding signed deviation (the
  first point uses the following sign);
- regions are discrete runs between median crossings and include both edge
  regions;
- each region's extremum maximizes absolute deviation from the median;
- a sustained 6–14 Hz peak anchors relative band identity; no qualifying peak
  leaves the bands unanchored;
- a band is significant only when its own peak/trough crosses the matching
  limit; insignificant regions have their significance vector cleared; and
- `per_freq=false` reduces lower limits to their global minimum and upper
  limits to their global maximum before testing. `per_freq=true` retains the
  frequency-specific ribbon.

EVA will preserve these discrete parity fields. Any interpolated crossing used
for drawing is display-only.

### Significance and lookup tables

The paper's inferential procedure is unambiguous: 200 matched surrogates, two
tails at 2.5% each, and `k=5` observations per tail for α=.05. EVA defines the
lower threshold as the fifth-lowest order statistic and the upper threshold as
the fifth-highest order statistic at each frequency. This is distinct from an
interpolated percentile.

The paper preset applies those order statistics independently at each
frequency. A global minimum/maximum envelope is retained only as an explicitly
named toolbox-compatibility or exploratory option. Every exported result must
record both the significance source and the threshold rule.

The repository currently exposes three conflicting artifacts:

1. `SIGLIM2.mat` identifies itself as a 200-repetition bootstrap table with
   α=.05 and α=.01 dimensions, but no maintained Python walkthrough consumes
   it directly.
2. The Python walkthrough Option A consumes older `SIGLIM.mat`, chooses the
   nearest duration, sampling rate, and aperiodic slope, then asks ABBA to
   collapse frequency-specific limits into one global envelope.
3. `general_sig_lims` defaults to only 20 repetitions and writes raw minima and
   maxima. Its default slope grid also does not reproduce the bundled table.

**Decision:** EVA will not bundle or label either upstream MAT table as a
paper-valid α=.05 source. Milestone 2 starts with deterministic on-demand
generation of 200 surrogates and the explicit fifth-order-statistic rule.
Lookup-table support stays unavailable until EVA owns a reproducible generator,
checksum, axis ordering, interpolation policy, and held-out validation. The
20-surrogate minimum/maximum envelope may be shown only as an explicitly
exploratory range, never as α=.05 significance.

The maintained per-recording Python surrogate path fits the input power
spectrum but passes sorted uniform random values to IAAFT rather than preserving
the original EEG amplitude distribution. Milestone 2 compared that behavior
with the paper's stated IAAFT procedure before choosing EVA's production
amplitude-distribution policy.

### Milestone 2 resolution

EVA follows the paper's stated on-demand procedure: finite observed EEG values
provide the target amplitude distribution, while a power-law fit to the
segment-aware Welch spectrum provides the target Fourier magnitudes. The
maintained Python `compute_pink_lavi` path's sorted-uniform input is therefore
not treated as a paper-valid oracle. It is a recorded compatibility difference.

The inferential configuration is deliberately narrow: 200 draws, two-sided
α=.05, and per-frequency fifth-lowest/fifth-highest order statistics. Twenty
draws or global minimum/maximum limits remain exploratory. EVA retains a final
IAAFT iterate when it reaches a stable fixed point or the iteration cap, records
complete diagnostics, and reports the nonconverged count.

No bundled lookup table is shipped. `SIGLIM.mat` and `SIGLIM2.mat` remain
reference artifacts only because the maintained generator, consumer, grids,
tail semantics, and file contents do not form one reproducible specification.

### WTPL scope and milestone 6 resolution

The maintained LAVI Python burst layer describes its WTPL/FieldTrip calls as
unvalidated placeholders, and the standalone WTPL repository is MATLAB-only.
EVA therefore does not treat either as an executable numerical oracle. Milestone
6 adds `generate_wtpl_oracle.py`, an independent Python implementation of the
published signed-lag equation and complex-plane fractional interpolation rule.
The committed fixture covers per-trial values, online condition means and
variance, valid-trial counts, strict baseline subtraction, edge masking, and
trial separation. Swift tests match the complete fixture and separately cover
phase resets, amplitude invariance, fractional lags, and the distinction from
ITPC. The upstream WTPL commit remains recorded for provenance and API context,
not copied implementation behavior.

## License boundary

Both repository roots contain the same MIT license. That does not erase
file-level provenance:

- `waveletLight.m` and `tfrLight.m` identify themselves as FieldTrip-derived
  GPL-3.0-or-later files;
- `iaaft_loop_1d.m` carries V. Venema's separate permissive notice; and
- the Python wavelet and surrogate modules state that they translate the MATLAB
  implementations but do not carry the complete source-file notices.

These checkouts are external black-box oracles only. EVA will independently
implement the published equations and behavior. No upstream source, MAT lookup
table, or participant example data is redistributed in EVA. If direct code is
ever proposed, it requires a fresh license review and the appropriate notice;
the current implementation plan assumes no such copying.

## External MFF policy

The two supplied recordings are approximately 1.5 GB together, each contains
257 channels at 1000 Hz, and each lasts about 12.7 minutes. They are valuable
end-to-end performance and correctness inputs but unsuitable repository
fixtures. Tests locate them through `EVA_RHYTHMICITY_MFF_ROOT` or the documented
temporary marker used when Xcode strips arbitrary environment variables.

`RhythmicityMFFIntegrationTests` loads both through EVA's `MFFReader` when that
external root is available. It runs the Milestone 1 direct LAVI/ABBA path on a
bounded 12-second window from the first channel at 6, 10, 20, and 40 Hz. It
then compares direct and production overlap-save LAVI on that same window and
feeds 2,048 observed samples through the complete aperiodic fit,
200-IAAFT-surrogate, fifth-tail, and significance-aware ABBA path using the
production FFT provider. The focused synthetic suite separately covers all 200
draws with the direct Morlet provider. CI skips the test when the folder is not
installed. The test never copies or persists the full waveforms or its
in-memory windows.

The current Milestone 3 local gate passed against both supplied recordings on
2026-09-11 in 125.364 seconds, including whole-recording ingestion, direct/FFT
parity, and bounded 200-surrogate production inference. This is not a release
performance target; detailed deidentified measurements are recorded in
`milestone3-benchmark.json`.

The Milestone 6 extension of that gate passed both recordings on 2026-09-11 in
117.466 seconds total. For each external file it additionally partitions 8,000
observed samples into four bounded trial containers, checks raw and baseline-
subtracted WTPL at 8, 10, and 20 Hz, and verifies direct-vs-production maps,
NaN masks, and valid counts. Maximum error remains below `1e-10`; participant
samples are not committed or exported.

The Milestone 7 extension additionally computes production five-cycle Morlet
power and signed-lag WTPL at 8, 10, and 20 Hz over a bounded 12-second observed
interval, then runs the P90/P75 detector and verifies finite thresholds,
segment-clamped intervals, one-cycle minimum duration, and analysis-only
boundary identity. It never converts bursts into artifact events.

## Regeneration

See `Tools/RhythmicityReference/README.md` for exact commands. A LAVI fixture
update must change the pinned commit and manifest deliberately, regenerate the
JSON, run the Python upstream tests, run `RhythmicityMilestone0Tests`, and
explain all numerical differences in this file. A WTPL fixture update must
regenerate the independent oracle, run `WTPLEngineTests` and
`WTPLIntegrationTests`, and document any equation or fixture-schema change
here.

`burst-python-oracle.json` is generated by the dependency-free
`generate_burst_oracle.py`. It pins the complete map inputs, percentile
thresholds, plateau representative, boundary/merge outcome, WTPL values and band
identity independently of Swift. Its SHA-256 is
`e6e01fd37cc4ad365b3ae3b1f51295a8cc075dc114541deb7890b35afca0de00`.
